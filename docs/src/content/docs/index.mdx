0security finds vulnerabilities in your software, proves them, and ships tested fixes. Create persistent security agents that watch your software, infrastructure and systems on a schedule, on every change or on demand, and run teams of them in parallel, with your own models, on your own infrastructure.

It runs on your machine, in your CI or in a container, with your own model key.

## Install

<Tabs syncKey="install">
  <TabItem label="macOS / Linux">
    ```bash
    curl -fsSL https://raw.githubusercontent.com/0sec-labs/0/main/install.sh | bash
    0
    ```

    `0` opens the browser app. The installer supports Apple Silicon macOS and x64 or ARM64 Linux. It installs a checksum-verified binary to `~/.0/bin` and adds it to your `PATH`. Set `INSTALL_DIR` to change the location.

    Windows is experimental: download `0-windows-x64.exe` from [Releases](https://github.com/0sec-labs/0/releases/latest).
  </TabItem>
  <TabItem label="Docker">
    ```bash
    docker run --rm -e ANTHROPIC_API_KEY \
      -v "$PWD:/work/source:ro" ghcr.io/0sec-labs/0:latest \
      scan source /work/source --runtime api --depth quick --cost-ceiling 2
    ```

    The image runs CLI commands. Mount your code and pass your model key explicitly. See [Docker](/docker/).
  </TabItem>
  <TabItem label="Source">
    ```bash
    git clone https://github.com/0sec-labs/0.git && cd 0
    pnpm install --frozen-lockfile && pnpm build
    node packages/cli/dist/index.js web
    ```

    Requires Node.js 24 or newer and pnpm. A source build does not install a global `0` command.
  </TabItem>
</Tabs>

Prefer the terminal?

```bash
export ANTHROPIC_API_KEY=...
0 scan source ./your-repo --runtime api --depth quick --cost-ceiling 2
```

Only scan systems you own or are authorized to test. See [Scope and authorization](/scope/).

## First scan

<Steps>

1. **Connect a model.** Open **Settings → Connections** and add a provider key or sign in. See [Models and keys](/models/).

2. **Start a mission or run a scan.** Press **New mission** and describe the job, for example "Review ./my-app for injection bugs". Or run `0 scan source`, `0 scan web` or `0 scan package` in a terminal.

3. **Open Findings.** Each finding links to its evidence. See [Findings](/findings/).

4. **Verify and fix.** Reproduce a finding, then generate and check a patch. See [Verify and fix](/verify-and-fix/).

</Steps>
