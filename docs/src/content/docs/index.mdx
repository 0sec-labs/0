## Find, verify, and fix

Choose the workflow for your target, then inspect its evidence and outcome—not
just its exit code—before treating a lead as confirmed or a repair as verified.

| Your task | Start here |
| --- | --- |
| Assess an authorized web or API target | [Scan workflows](/scan-workflows/) and [scope files](/scope/) |
| Review source or a package | [`review` and `audit`](/commands/#start-by-task) |
| Reproduce a finding or check a repair | [Verification results](/verification-result/) and [`secure`](/commands/#secure) |
| Evaluate an AI endpoint or agent integration | [`eval` and `agent-assure`](/research-workflows/) |
| Investigate identity and access paths | [Engagements](/engagements/) |
| Hunt source variants, inspect binaries, or use kernel evidence | [Research workflows](/research-workflows/) and [0verse prerequisites](/commands/#binary) |

`secure` brings repository investigation, reproduction, repair attempts,
regression tests, and independent repair verification into one workflow.
It runs on the current worker, not in a newly provisioned sandbox. Publication
is opt-in, and a completed run can still contain blocked findings: inspect
the individual outcomes before accepting a patch.

## Connect your models

Use [API Keys](/api-keys/) to establish a supported model connection, then
choose models in the [console](/console/) or [configuration](/configuration/).
[Role-model assignments](/configuration/#multi-model-role-routing) can use
different models supported by that provider or gateway. Child agents inherit
the parent connection; they do not automatically discover or switch to another
provider account. Model choice is not a claim of automatically optimal routing.

## Extend and automate

[Build a Hackstore extension](/hackstore/) to add your own tools to 0, test
them locally, and share them with other users.

The local CLI needs no 0cloud account when you use your own model connection.
[Hosted inference](/getting-started/#hosted-models) keeps tools in your environment.
[Managed security work](/getting-started/#managed-work-and-onboarding) has
separate scope, access and commercial terms.
