## Find, verify, and fix

Choose the scan for your target, then inspect its evidence and outcome—not
just its exit code—before treating a lead as confirmed or a repair as verified.

| Your task | Start here |
| --- | --- |
| Assess an authorized web or API target | [Scans](/scans/) and [scope files](/scope/) |
| Review source or a package | [`scan source` and `scan package`](/commands/#scan-source) |
| Reproduce a finding or check a repair | [Verification results](/verification-result/) and [`scan repair`](/commands/#scan-repair) |
| Evaluate an AI endpoint or agent integration | [`eval` and `agent-assure`](/research-workflows/) |
| Investigate identity and access paths | [Scope](/scope/#authorized-engagements) |
| Hunt source variants, inspect binaries, or use kernel evidence | [Research workflows](/research-workflows/) and [0verse prerequisites](/commands/#research-binary) |

`scan repair` brings repository investigation, reproduction, repair attempts,
regression tests, and independent repair verification into one workflow.
It runs on the current engine, not in a newly provisioned sandbox. Publication
is opt-in, and a completed run can still contain blocked findings: inspect
the individual outcomes before accepting a patch.

## Connect your models

Use [API Keys](/api-keys/) to establish a supported model connection, then
choose models in the [console](/console/) or [configuration](/configuration/).
[Role-model assignments](/configuration/#multi-model-role-routing) can use
different models supported by that provider or gateway. Child agents inherit
the parent connection; they do not automatically discover or switch to another
provider account. Model choice is not a claim of automatically optimal routing.

## Extend and automate

[Build a plugin](/plugins/) to add your own tools to 0, test
them locally, and share them with other users.

The interactive console uses your connected API key or provider subscription
for model inference. The [enterprise platform direction](/roadmap/#enterprise-platform)
adds organization-wide automation and use-case plugins around the open core.
Discuss scope, deployment, and available integrations with the team.
