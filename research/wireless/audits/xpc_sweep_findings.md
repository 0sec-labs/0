# XPC/IPC Security Sweep — wifianalyticsd, bluetoothaudiod, wifip2pd

Scope: existing decompilation artifacts only (`research/wireless/decomp/re_wifianalyticsd.c` 116,504 lines; `re_bluetoothaudiod.c` 92,442 lines; `re_wifip2pd.c` 844,362 lines; `fmb_arm64e.c` 20,781 lines for dedup). No new Ghidra runs. Method: automated pattern battery over the full text of all four files (regex on raw file content — no 4MB window limitation; every line of all three daemons was scanned), then targeted manual reads of every candidate site plus call-chain tracing to entry points. All line numbers below refer to the named `.c` file. Confidence labels: **confirmed** (static evidence complete) / **likely** (evidence strong, one link unverified) / **uncertain**. Inferences are marked `[INFERENCE]`.

Reference bug family (from `audits/findmy_rotation.md` §2 and `audits/continuity_beacons.md` §3, items 2–4): Swift `Optional<Bool>` fail-open gate where the `.none` tag (`-1` / `0xFF`) takes the privileged path (`fmb_arm64e.c:10003`), and the release-then-return UAF at `fmb_arm64e.c:12127-12131` (FUN_100012438). Both are **deduplicated** (see final section) and used here only as the shape to hunt.

## Findings ranked by exploitability

### 1. bluetoothaudiod — NULL-deref/UB in 8 XPC volume/preset handlers (untyped UUID argument)
- **File:lines:** `re_bluetoothaudiod.c:38140-38143, 38179-38184, 38227-38232, 38277-38282, 38327-38332, 38372-38377, 38424-38429` — handlers `_handlekCBMsgSetVolumeMsg:reply:` @`100035ef4`, `_handlekCBMsgSetVolumeOffSetMsg:reply:` @`100035fd8`, `_handlekCBMsgSetVolumeMuteMsg:reply:` @`1000361c4`, `_handlekCBMsgWriteVolumeAudioInputMsg:reply:` @`1000362c8`, `_handlekCBMsgSetMicrophoneMuteMsg:reply:` @`1000364b4`, `_handlekCBMsgWriteMicrophoneAudioInputMsg:reply:` @`1000365b8`, `_handlekCBMsgReadPresetsMsg:reply:` @`1000367a4`, `_handlekCBMsgSetActivePresetMsg:reply:` @`10003685c`.
- **Shape:** `xpc_dictionary_get_value(msg, "kCBMsgArgLEAudioDeviceUUID")` result is passed directly to `xpc_uuid_get_bytes` and then `NSUUID::initWithUUIDBytes_` with **no null/type check** (e.g. `re_bluetoothaudiod.c:38150-38153`).
- **Attacker gain:** any client entitled to `com.apple.bluetoothaudiod.cb` (see finding 5) sends a message missing the UUID key (or with a non-UUID type) → `xpc_uuid_get_bytes(NULL)` → NULL-deref or UB inside NSUUID init. Reliable daemon crash (DoS). Remote reachability: XPC clients only, not wireless peers.
- **Confidence:** confirmed (static; not dynamically reproduced).

### 2. bluetoothaudiod — heap OOB read in ASCS codec-config TLV parse (remote BLE peer reachability)
- **File:lines:** `re_bluetoothaudiod.c:35838-35885`, function `ASCSServerService::codecConfigRequest:` @`10003344c` (header 35721); reached from `ASCSServerService::receivedWriteRequest:` @`100032d80` (header 35531) when a GATT write hits the ASCS Control Point characteristic with opcode 1 (`re_bluetoothaudiod.c:35586-35592`).
- **Shape:** a one-byte attacker length (`local_97`, read at 35838, max 255) declares the codec-config TLV blob; `readNumBytes_toData_` (`DataInputStream::readNumBytes_toData_` @`10002cf50`, body 31234) appends to the NSMutableData **only on a fully successful read** — on a truncated write the buffer stays empty. The parse loop nevertheless runs `while ((int)uVar12 < (int)(uint)local_97)` (`re_bluetoothaudiod.c:35880`) indexing `*(byte *)(IVar5 + 1 + idx)` (`re_bluetoothaudiod.c:35846`, `IVar5` = `bytes()` of the possibly empty NSMutableData) and `___memcpy_chk(&local_9c, IVar5 + idx + 2, len, 4)` (`re_bluetoothaudiod.c:35863`). The `___memcpy_chk` guards bound the 4-byte destination, **not** the OOB source read.
- **Attacker gain:** any paired BLE central writing a truncated codec-config command → read up to 255 bytes past a zero-length heap buffer (NULL if `bytes()` returns nil → crash). Also per-TLV payload lengths are ignored (`uVar12` advances by header+declared length without bounds against actual data), so TLV desync is inherent. Gain is limited to OOB-read-influenced codec state and DoS — no write primitive observed.
- **Confidence:** likely (static; truncation semantics of `readNumBytes_toData_` verified at `re_bluetoothaudiod.c:31234-31270` `[INFERENCE: dynamic behavior of CoreBluetooth write fragmentation not tested]`).

### 3. wifip2pd — decompression bomb in Wi-Fi Aware config loader (resource exhaustion)
- **File:lines:** `re_wifip2pd.c:304730-304748`, function FUN_100165e2c @`100165e2c`; sole caller FUN_1001673e8 @`1001673e8` at `re_wifip2pd.c:305655`.
- **Shape:** `NSData decompressedDataUsingAlgorithm:error:` (algorithm from a global pointer, `re_wifip2pd.c:304734-304737`) with **no cap on decompressed output**, result fed straight into `Foundation::JSONDecoder::_decode` (`re_wifip2pd.c:304763`).
- **Provenance:** the caller FUN_1001673e8 iterates **Keychain items** (`kSecAttrAccount`/`kSecValueData`, `re_wifip2pd.c:305560-305600`; "Internal Error while accessing Keychain" at `re_wifip2pd.c:305726`) and passes each item's `Data` value to the decompress+decode. A small (compressed) keychain blob forces the daemon to allocate the full expanded size.
- **Attacker gain:** DoS via memory exhaustion, **if** attacker-influenced bytes reach that keychain item (e.g. cached peer attributes written by an upstream handler). The keychain-internal provenance was not traced to a wireless-reachable writer.
- **Confidence:** likely (sink confirmed; attacker influence on keychain contents **uncertain** `[INFERENCE]`).

### 4. bluetoothaudiod — attacker-string selector dispatch, bounded
- **File:lines:** `re_bluetoothaudiod.c:38095-38106`, `LEAudioXPCSession::handleMsg:` @`100035d38`.
- **Shape:** selector built as `"_handle%@Msg:reply:"` from the attacker-controlled `kCBMsgId` **string** via `NSSelectorFromString`, dispatched if `_objc_opt_respondsToSelector` passes.
- **Assessment:** the format string pins both prefix and suffix, so only `_handle<X>Msg:reply:` selectors are invocable — all of which are intended handlers (`re_bluetoothaudiod.c:38108-38503`). An attacker can reach any such handler regardless of message semantics (cross-handler argument confusion, e.g. ReadPresets handler invoked with SetVolume args); all downstream args go through nil-safe `numberForKey_optional_dict_` helpers. **No arbitrary selector injection.**
- **Confidence:** confirmed (bounded invocability); impact low.

### 5. bluetoothaudiod — mach-service gate is entitlement-only (no signing/audit-token check)
- **File:lines:** `re_bluetoothaudiod.c:8424-8446`, `LEAudioXpcService::_handleConnection_` @`10000b910`; listener created in `LEAudioXpcService::initWithName:sessionClass:` @`10000b6fc` (`xpc_connection_create_mach_service(name, main_q, 1)` at `re_bluetoothaudiod.c:8316`); entitlement string `"com.apple.bluetoothaudiod.cb"` set at the sole init site `re_bluetoothaudiod.c:50691`.
- **Shape:** gate requires `xpc_connection_copy_entitlement_value(conn, name)` to be a bool `true`; anything else → log + `_xpc_connection_cancel` (`re_bluetoothaudiod.c:8446`). **Deny-by-default confirmed** — this is the correct shape, in contrast to the fmb fail-open.
- **Residual:** the entitlement is a binary gate; no code-signing identity or audit-token validation beyond it, so any entitled process reaches all session handlers (finding 1's crash surface).
- **Confidence:** confirmed.

### 6. wifip2pd — accept-time client identity validated but not enforced at accept
- **File:lines:** `re_wifip2pd.c:788378-788384` (`_TtC12wifip2pdCore9XPCServer::listener_shouldAcceptNewConnection_` @`1003f3a9c`) → FUN_1003f2bd8 @`1003f2bd8` (`re_wifip2pd.c:788100-788375`) → FUN_1001c7568 @`1001c7568` (`re_wifip2pd.c:381459-381614`).
- **Shape:** FUN_1001c7568 builds the client identity from the audit token: `SecTaskCreateWithAuditToken` → `SecTaskCopySigningIdentifier` → `SecTaskCopyTeamIdentifier` → `SecTaskGetCodeSignStatus`, then a bitmask test `((isDynamicallyValid | isPlatformSigned | platformPath) & status) == (isDynamicallyValid | isPlatformSigned)` (`re_wifip2pd.c:381576-381582`; DAT_100548120 = isDynamicallyValid, DAT_100548124 = isPlatformSigned, DAT_100548128 = platformPath, populated lazily via FUN_1001c6918/6938/6958). Deny-by-default (missing signing identifier ⇒ `bVar2 = false`). **But the result is only stored as `XPCSession.clientBundleID`** (`re_wifip2pd.c:788259-788261`) — the connection is accepted regardless; enforcement happens per-request.
- **Enforcement path (verified):** privileged XPCResponder methods (createSubscribe/et al., FUN_1002e3950/1002e3c04/1002e3ebc/1002e4458/1002e47b0, `re_wifip2pd.c:620300-621000`) each call FUN_1002e61d8 @`1002e61d8` (`re_wifip2pd.c:622296-622380`) which, when `wifiAwareEntitlementsManager` is set, runs FUN_10038f224 @`10038f224` (`re_wifip2pd.c:728192-728395`) — an AND-reduce of every required capability ("Public"/"Subscriber" literals at `re_wifip2pd.c:728226-728240`) against the client's granted entitlements, deny-by-default on empty/missing lists (`re_wifip2pd.c:728212-728214`), and **invalidates the connection** on failure (`re_wifip2pd.c:620396-620420`).
- **Residual weakness:** the codesign bitmask accepts any Apple-platform-signed, dynamically-valid binary that is not the on-disk platform binary (platformPath flag rejected, but a re-signed/injected Apple-platform binary clears the test). Impact bounded by the per-request entitlement gate.
- **Also noted:** PID/process-name cache (`FUN_1003f3bc4` @`1003f3bc4`, `re_wifip2pd.c:788430-788456`): when an incoming connection's PID equals the cached `lastProcessID`, the cached `lastProcessName` is reused (`re_wifip2pd.c:788162-788176`). PID recycling lets a different process be logged under the previous process's name — log misattribution only.
- **Confidence:** uncertain (design observation; no direct gain due to per-request enforcement).

### 7. wifip2pd — dead-code entitlement checker FUN_1001c6f04

- **Confidence:** uncertain (harmless dead code, or a gate removed during linking; hardening note only).

### 8. wifianalyticsd — unvalidated MDM plist parse (out of wireless threat model)
- **File:lines:** `re_wifianalyticsd.c:39887-40072`, FUN_100048d28 @`100048d28` (dispatched from `ManagedConfiguration::profileChangedCallback_` @`39858`); `NSPropertyListSerialization::propertyListWithData:options:format:error:` at `re_wifianalyticsd.c:39954-39955` with options=0 and no length/type validation; keys `megawifiprofile_diagnostic_metrics_enabled` / `_period_ms` / `coredata_diagnostic_metrics_enabled` extracted with nil-guards only; `period_ms` drives timer configuration.

## Pattern-by-pattern NO-MATCH statements

### Pattern 1 — fail-open Optional/tag gates (`== -1` / `0xFF`-tag privileged default)
- **wifianalyticsd:** NO MATCH. The only `== -1` sites (`re_wifianalyticsd.c:90738, 90748`, `WADatapathDiagnosticsMessageSubmitter::submitDPEMessage` block) select between `"NoTE"` and `"TE_%d"` **log strings** — formatting, not privilege. All `>> 0x3c & 1` hits are Swift `_StringObject` tag-bit tests in FUN_10000c6e8/10000c840 (string-representation dispatch). `0xffff` at `re_wifianalyticsd.c:42300` is a binning sentinel.
- **bluetoothaudiod:** NO MATCH. ASE-count byte clamp at `re_bluetoothaudiod.c:3306-3310` (`ASCSInterface::handleControlPointUpdate` @`100006a00`) remaps `0xFF`→1 **before** the loop — fail-closed; `local_94[0] - 3 < 0xfffffffe` (`re_bluetoothaudiod.c:3320`) is an opcode range test; all `cigID()==-1` comparisons are error-code checks (e.g. `re_bluetoothaudiod.c:15212, 21005`); `param_3 == -1 || param_4 == 0xff` at `re_bluetoothaudiod.c:17196` logs and skips — fail-closed.
- **wifip2pd:** NO MATCH for privilege/data gates. All sampled `0xFF`-tag sites are Swift `Hasher.hash(into:)`/`Equatable` conformances (FUN_1000e1738..1000e1e64 `re_wifip2pd.c:188101-188465`; FUN_1001dab44 `re_wifip2pd.c:400665-400671`; FUN_1001471d0 `re_wifip2pd.c:277947-277954`; FUN_1001c14dc `re_wifip2pd.c:374734-374737`) where the tag only selects which payload is hashed/compared. The `(tag == 0xff) || (tag & 1)` shapes at `re_wifip2pd.c:66213, 66670` (`AppleDevice.GatewayMonitor` change detection) treat `.none` as "update gateway" — correct-by-default semantics, not privilege escalation. The `((x >> 0x3c & 1) != 0) && (y == -1)` shapes (`re_wifip2pd.c:778969, 785878, 786302`, FUN_1003f0868 @`1003f0868` 24 bytes) early-**return** (skip work) — fail-closed.

### Pattern 2 — unvalidated inputs into privileged ops
- **wifianalyticsd:** only the MDM plist (finding 8). The AWD/protobuf path is internal (`instantiateAWDProtobufAndPopulateValues_` / `streamPBCodeable:additionalDictionaryItems:` `re_wifianalyticsd.c:38302-38483`, fed by internal `DatapathMetricGetter`, not external); the `lastPB` memcpy at `re_wifianalyticsd.c:37912` is guarded `IVar3 < 0x2801` into a buffer pre-sized `initWithCapacity_:0x2800` + `setLength_:0x2800` at init (`re_wifianalyticsd.c:37364-37380`) — exact-fit, verified safe.
- **bluetoothaudiod:** finding 2 (codec-config TLV OOB read). `FUN_10002887c` @`10002887c` (`re_bluetoothaudiod.c:27883, 27952`) is the CSIS s1 key derivation — destination `calloc(ceil(len/16),16)` sized from the length itself (`re_bluetoothaudiod.c:27880`), second memcpy's three callsites all pass fixed 16-byte buffers/constant lengths (28182 region). Verified safe. PACS parse desync (`handlePACUpdate_withType_` @`10000cd24`, `re_bluetoothaudiod.c:9463-9593`: inner loops consume TLV headers without payload lengths) is a robustness issue, no memory corruption. ASE parser ignores `readUint8_` return values (`re_bluetoothaudiod.c:3299-3318`) but targets are zero-initialized — no uninitialized stack read. - **wifip2pd:** finding 3 (decompression bomb). NO MATCH beyond finding 3.

### Pattern 3 — memory bugs (UAF shapes, unchecked allocs, off-by-one)
- **wifianalyticsd:** NO MATCH. All `_swift_release(X); return Y;` candidates (`re_wifianalyticsd.c:2761-2762, 4795-4796, 7984`) release a different variable than is returned — none matches the fmb `release(X); return X` shape. All malloc sites are Swift stdlib string/array internals with SCARRY8 overflow traps (`re_wifianalyticsd.c:7669-7900`) or fixed-size ObjC alloc stubs (36567/36582/58320/58766/63659), nil-checked. No `<=`-against-count parse loops.
- **bluetoothaudiod:** NO MATCH. No release-then-use shape in the file. App-level allocs: `_malloc_type_malloc((count & 0xff)+1)` in `sendEnableRequestForDirection:...` @`100003040` (`re_bluetoothaudiod.c:1449`) and `sendUpdateMetadataRequestForDirection:...` @`1000035b8` (`re_bluetoothaudiod.c:1637`) — buffers written at `[2..count+1]`, exact fit; calloc pair in FUN_10002887c freed on all paths incl. error (`re_bluetoothaudiod.c:27922-27931`). - **wifip2pd:** NO MATCH in sampled regions. Allocations are `_swift_allocObject` sized from type metadata, not peer lengths; no release-then-use shapes in ~700 sampled lines across the target clusters; loop bounds in FUN_10038f224 and array-grow helpers (FUN_100073ae0/100073810/100073c4c) bound exactly with `count>>1` capacity rechecks. `[INFERENCE]` the full 844k-line file was scanned by regex for the release-then-return shape (`_swift_release\((\w+)\);\s*return \1;` and the `objc_release` variant): **zero matches** in all three daemons — the fmb FUN_100012438 UAF shape (`fmb_arm64e.c:12129-12130`) is unique to that binary among the audited set.

## Method note / limitations
- Full-text regex scan of every line of all three daemons (no sampling, no grep 4MB window) for the pattern battery: Optional-tag gates (`== -1`, `== 0xff`, `!= 0 && == -1`, tag-bit tests), plist/JSON decode, `xpc_*` sender-validation APIs, `memcpy`, malloc-family, release-then-return shapes.
- Call-chain tracing was done by full-text reference search in the decompile; `[INFERENCE]` marks cases where ObjC dispatch tables or data-section pointers could hide references that never appear as text.
- No dynamic verification: every finding is static; exploitability statements are reasoned, not executed.
