# zero-http

Host-scoped target HTTP transport, separate from provider inference clients. The engine supplies durable request/rate/byte accounting hooks; this crate enforces physical destination and response bounds. It does not create findings or make target responses authoritative.

`Client::new(policy, auth)` captures a canonical public policy and a private, nonserializable `StaticAuth`. `prepare` derives a credential-free immutable request intent. `execute` consumes it with cancellation and an `ExecutionHooks` implementation. `normalize_policy`, `normalize_intent`, `canonical_origin`, and `profile_sha256` are pure functions for journal validation. Policy hashes use canonical `serde_json::Value` serialization.

Each hop checks URL, host and path, resolves all A/AAAA addresses, rejects any forbidden address, obtains a durable dispatch permit, rechecks scope, then connects to one approved literal address. Original Host and TLS certificate/SNI identity remain bound to the URL. HTTP/1 connection and DNS/TLS socket futures are owned by the caller: no background resolver or pooled connection task survives cancellation or a dropped execution. There is no ambient proxy, cookie jar, automatic target retry or address fallback. Cancellation drains only bounded accounting settlement after closing network IO.

Host policy selects Manual, Error, or Follow redirects (at most five followed hops). Every hop obtains its own account permit. Cross-origin redirects remove all caller headers; saved auth and attribution only apply to the original origin. POST 301/302 and applicable 303 responses become GET; 307/308 retain the owned body. Completed redirect observations retain the checked next URL before another hop is admitted.

Request bodies are bounded by 1 MiB. Both request and response header sections are bounded by 64 KiB/128 fields. Compressed response bytes and every decoded stage are independently bounded by 16 MiB. Identity, gzip/x-gzip, zlib-framed deflate and Brotli are supported, with at most four stacked encodings. Concatenated members are decoded rather than silently dropped. Limits, malformed encodings and partial responses are failures, never successful truncation. Full 16 MiB responses and invalid UTF-8 body bytes remain representable; the engine can retain redacted bytes in artifact chunks.

Static credentials bind to exact original origin and public host-managed revision/header names. Rotate the revision whenever credentials change. Known secret values, bearer/basic components and cookie values cannot enter public intent; exact and URI-encoded reflections are redacted before return. Sensitive response headers, including new Set-Cookie values, are always masked. Redaction uses a bounded NFA matcher, cooperative body processing and a separate 16 MiB output ceiling. Returned hashes must describe redacted retained evidence, not unavailable raw secrets. Arbitrary transforms of unknown credentials are not claimed detectable. Stateful login, cookie capture, reauthentication and credential rotation during an active actor are not implemented.

The default Unix resolver captures bounded `/etc/hosts` and the first `/etc/resolv.conf` nameserver. It sends owned UDP A/AAAA queries with bounded CNAME following and TCP fallback for truncated packets. It checks response identity/question and ignores unrelated additional records. Both address families must complete successfully; no implicit search suffixes, DNS cache, NSS modules, mDNS, DNSSEC validation or detached blocking `getaddrinfo` fallback are used. Other platforms require an explicit trusted `Resolver`. Resolver and clock injection, and optional additional TLS roots, are host-only runtime configuration—not model arguments or an insecure certificate mode. Absolute canonical names are used. Resolver infrastructure DNS packets precede target dispatch; `NeverDispatched` means no target HTTP connection, not that no DNS packet existed.

Policy preserves explicit deny precedence, wildcard subdomains excluding the apex, IPv4 CIDR rules, mapped-IP exclusions and the legacy explicit-private-base floor. DNS resolving a public-looking base to private space does not create a private anchor. Path prefixes match segment boundaries. Encoded separators, NUL, and encoded-percent path forms are rejected conservatively; this is not a claim about every backend's URL-routing interpretation. Host-side rate limits, jitter and durable shared budgets live in the engine/store integration. Dynamic scope grants, engagement/autonomy modes, WAF adaptation, browser/crawl/form flows, OAST and scanner workflows remain separate work.

`PossiblyDispatched` is conservative from permit receipt before TCP connect. A host admission transaction can commit just before cancellation wins, so the engine must also inspect durable permits, not rely solely on the in-memory flag. Complete HTTP error statuses are known responses. Incomplete/cancelled post-dispatch effects are never automatically replayed. Hook settlement must be idempotent: a store-only bounded drain can observe a permit whose prior settlement committed before its waiter was cancelled.

Local tests exercise actual HTTP and TLS listeners, DNS UDP/TCP, original-host certificate validation, all-address rejection, redirects/auth stripping, header/encoding/expansion limits, full-size binary bodies, fake-clock DNS deadlines and cancellation socket closure. Fixtures contain synthetic public test certificates and keys only. No live targets or paid providers are used.
