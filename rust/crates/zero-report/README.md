# Native report rendering

Pure JSON, SARIF, Markdown and HTML renderers for legacy `ScanReport` data. The reference is
`packages/cli/src/formatters/{json,sarif,markdown,html}.ts`. This crate does not discover,
verify, redact, publish, or authorize disclosure of findings. Report status and
verification fields are preserved as supplied data, never inferred from model
confidence or a successful tool exit.

`Report::parse` bounds input to 16 MiB and validates the renderer's required
fields and severity/action discriminants. It preserves additive fields in JSON.
SARIF 2.1.0 retains original rule IDs, severity levels, stable fingerprints,
proof-step data, evidence and verification metadata. Rules are deduplicated in
first-seen order; findings are not deduplicated or silently dropped. Explicit
failed scan status and zero scores/confidence survive. The legacy default
`executionSuccessful: true` when absent is retained for compatibility; rendering
is not evidence that execution occurred.

The caller supplies the exporting version. JSON object ordering and whitespace
are not a byte-for-byte compatibility promise. No action inside a proof step is
executed. Like the legacy renderer, evidence/HTTP headers are exported as supplied;
apply the authorized redaction policy before sharing a report. No upload occurs.

SARIF expansion is conservatively bounded before allocation, including repeated
long target URIs in proof steps. Oversized reports fail instead of truncating
findings. PDF, terminal presentation, artifact persistence and
scanner integration remain separate work.

The checked-in SARIF fixture is generated by the actual TypeScript formatter,
with only the shared version constant replaced by `fixture-version`:

```sh
bun rust/crates/zero-report/tests/fixtures/generate.ts
cargo test --manifest-path rust/Cargo.toml -p zero-report --locked
```

Rust tests compare parsed JSON semantics, all severity levels, duplicate rules,
proof action types, optional metadata, explicit false/zero, additive JSON fields,
malformed input, and bounded expansion. Fixtures contain no real credentials,
network activity or security findings.

`Report::markdown()` preserves legacy summary/warnings, finding status,
CVSS/confidence/triage, reproduction steps, remediation and request/response
sections. Ordinary enriched report output matches a checked-in golden generated
by the actual TypeScript formatter. JSON and SARIF behavior is unchanged.
Markdown output is capped at 64 MiB; over-limit output fails before CLI writes.

Intentional differences from the TypeScript renderer:

- User text is escaped as text, including table separators, HTML and link/image
  markup. Literal references remain text; no user-supplied Markdown link syntax
  is enabled. Code fences grow beyond embedded backtick runs, language labels
  are restricted, and unsafe control characters appear as visible escapes.
- Empty reports say “No findings reported” and do not assert target safety or
  successful execution. Missing Markdown-only metadata says “not supplied”; it
  is not inferred. Malformed present fields fail this renderer without changing
  JSON/SARIF acceptance.
- Evidence is limited to 4,000 Unicode scalar characters per block, with exact
  elision counts outside the fence. This avoids TypeScript UTF-16 surrogate
  splitting. The first 20 PoC steps are shown; further steps are explicitly
  counted. Lossless evidence remains available in JSON/SARIF.

Rendering does not verify supplied claims, remove secrets, fetch references,
execute examples, or authorize disclosure. Full-screen presentation and
scanner/managed-worker integration remain separate work.

`Report::html()` produces a deterministic, self-contained report based on the
legacy HTML formatter's styles, severity order, supplied severity counts,
finding cards, status/confidence/CVSS/rank/deduplication fields, warnings and
timeline. The TypeScript HTML golden fixture normalizes only its generated-time
footer; tests compare representative DOM field contents and ordering. Full HTML
byte parity is intentionally not claimed:

- Every supplied text context is HTML-escaped, including category, depth, URLs,
  references, remediation, language labels and code. URLs remain text rather
  than active links. No scripts, images or external resources are emitted; a
  restrictive CSP additionally disables resource fetching and script execution.
- Supplied PoC steps, CVSS vectors, triage and remediation reach the HTML even
  though the legacy HTML formatter omits them. Evidence uses the Markdown
  4,000-Unicode-character limit and explicit elision notices outside code;
  the legacy HTML renderer silently cuts at 2,000 UTF-16 units. Steps beyond
  the first 20 have a visible omitted count. Missing evidence is marked.
- Empty findings never imply a clean target. The legacy inferred risk badge is
  omitted; supplied severities and statuses remain visible with a notice that
  rendering does not verify them. Missing metadata is marked “not supplied”.
  No export-time clock is invented, so repeated renders are identical.

HTML escapes are written into a buffer capped at 64 MiB, including expansion;
errors return no partial CLI stdout. JSON, SARIF and Markdown output contracts
remain unchanged. PDF, browser opening, uploads and scanner orchestration remain
outside this renderer.
