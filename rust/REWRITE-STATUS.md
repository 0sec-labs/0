# Rust rewrite status

Updated 2026-09-19 for generation-bound interactive workspaces, repair bundles
and managed-cloud source integration. This is a feature
inventory, not a percentage estimate. A bounded working workflow does not prove
full TypeScript parity, general security effectiveness, platform support or
production readiness. Production CLI routing remains TypeScript.

| User workflow | Current evidence and remaining scope |
| --- | --- |
| Scoped HTTP investigation | Native scan, adaptive requests, host scope, accounting, cancellation, retained reports and retries are implemented with executable fixtures. Browser sessions, multiple principals/reset and specialist verification remain incomplete. See `crates/zero-cli/tests/scan.rs`, `crates/zero-engine/tests/scan_authority.rs`. |
| Local source review | Dirty/untracked workspace selection, adaptive source tools, cited hypotheses, archive retention and source-independent history/report work. Diff/package profiles and complete legacy workflow parity remain open. See `SOURCE-WORKFLOW.md`, `crates/zero-cli/tests/review.rs`. |

Private npm registry authentication, dependency graphs and OCI acquisition remain open. See `SOURCE-ACQUISITION.md`, `NPM-ACQUISITION.md`. |

| Repair and export | Native repair admission, two freshly materialized candidate matrices, independent report and archive-backed unified patch export are implemented. No original checkout is changed. A separate private workspace workflow now supports versioned edits, fresh offline Docker tests and export. Explicit host application checks the exported baseline, retains originals in a journal and supports interruption recovery without replacing later user changes. Validated native repairs can also export a checked archive bundle for explicit host application and rollback, preserving the independent frozen-plan assessment without claiming general repair safety. PR automation and broader repair workflows remain open. See also `WORKSPACE-EDITING.md` and `WORKSPACE-APPLY.md`. See `crates/zero-cli/tests/support/review_repair.rs`, `crates/zero-engine/src/native_repair_export/tests.rs`. |
| Interactive delegated investigation | Sessions, durable queues/steering/questions/approvals, delegation and native console/TUI primitives exist. Explicit offline Docker pipe sessions now support actor-owned create/write/read/close across turns, durable one-use writes, bounded transcripts and joined cleanup. A standalone editable workspace actor now supports allowlisted private edits, exact-generation Docker tests and offline exports with final dispatch ownership/budget checks. Interactive pipe sessions can now start from an explicit edited generation and preserve process state across turns; later source edits revoke new writes to old sessions, and guest mutations never silently become exported edits. True PTY behavior, delegation/other capability combinations, full tool coverage and product UX parity remain incomplete. See `crates/zero-cli/src/args.rs`, `crates/zero-tui/README.md`. |
| Providers and credentials | Responses/Chat/Anthropic, native Gemini and explicit Ollama chat streaming adapters, bounded credentials and Entra refresh exist. Ollama preserves thinking and ordered tool replay, requires final usage, and supports credential-free explicit local profiles without starting a server or pulling models. All provider tool dispatch requires final representable accounting; known budget overages stop subsequent tool dispatch; signed replay/context and offline retries are locally qualified. Complete legacy provider/login/process-provider coverage and live qualification remain incomplete. See `crates/zero-provider/README.md`. |
| Sandbox and plugin execution | Pinned Docker/smolvm execution and language-neutral persistent worker transport exist. Actor-owned persistent workers and explicit CLI worker policy are integrated. | Self-improvement | Budgeted strategy generation, independent holdouts/canaries, eligibility and guarded activation exist for bounded advisory strategy artifacts. `evolve-python run/status` now connects one paid source-only Python proposal to independent paired offline evaluation, with original-session accounting, one-use protected suites, inert retries and joined cancellation. `evolve-python search run/status` adds model-chosen public Development experiments, measured feedback, exact-source selection and voluntary stopping. Final private evaluation is terminal; original-session spending, deadlines and cancellation remain host-controlled. Local fixture and actual Docker qualification do not grant production eligibility. Broader harness changes and code promotion remain incomplete. See `AUTONOMY.md`, `CODE-EVOLUTION.md`, `PYTHON-SEARCH.md`. |
| Managed cloud product | Native grant/result producer and cloud contract/persistence/admission/accounting helpers exist. Authenticated terminal delivery and durable lost-acknowledgement retry are integrated in the cloud repo with local Rust/PostgreSQL/HTTP fixtures. A one-use command-start gate and local subprocess execution lifecycle are integrated with PostgreSQL fault fixtures. An explicit E2B adapter now has bounded transport, create-before-bind recovery identity and read-only recovery, qualified with local SDK-shaped fixtures. An opt-in recovery-only poller now selects content-addressed historical runtime/account configuration and retries staged delivery without fresh execution. Remote isolation/template qualification, authoritative historical inventory and financial reconciliation, production activation and dashboard product integration remain incomplete. Cloud source integration checkpoint is `84c09573`, independently reviewed with 252 combined tests and three service typechecks; source integration does not qualify historical drain evidence or authorize monetary closure.
